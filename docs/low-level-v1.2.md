# v1.2 — аудирование и level-up

Спецификация недель 9–12. Процессы те же: `core` и `ai-worker`. Появляется обязательное содержимое бакета — учебные аудио. Бакет под бэкапы уже есть с v1.0.

## 1. Результат

Ученик слушает текст своего уровня, пишет конспект по-английски и получает оценку по смыслу и по языку. Когда текущий модуль плана завершён, открывается экзамен. Новый `current_level` записывается только если судья экзамена поставил уровень выше текущего.

Готово, когда один и тот же текст не синтезируется заново на каждого ученика, повторная сдача конспекта не создаёт второй оценки, а провал экзамена оставляет прежний уровень.

## 2. Аудирование

Материал общий, не на пользователя.

`listening_materials`: `level`, `topic`, `transcript`, `audio_object_key`, `key_facts`, `status` (`draft|published`).

`key_facts`:

```json
{
  "facts": [
    "The meeting moved to Thursday.",
    "Anna will send the notes."
  ]
}
```

На уровень и тему один опубликованный текст. В каталоге на старте релиза не меньше 12 опубликованных текстов: по два на A1–C1 и два запасных. Их готовит офлайн-задача `author_listening`, её запускают вручную, не на каждый заход ученика.

Задача зовёт `gpt-6.1-terra` (`reasoning_effort=low`) за текстом 120–180 слов и списком из 4–6 фактов, затем один раз Cartesia: тот же снимок `sonic-3.6-2026-08-27`, тот же голос, что у ментора, файл PCM кладётся в бакет с префиксом `listening/{id}.wav` (PCM оборачивается в WAV при сохранении, чтобы плеер браузера открыл его без работы). В строку пишется ключ объекта. Повтор задачи с тем же id не вызывает синтез, если ключ уже заполнен.

Выдача:

```
GET /v1/listening/today
→ {
  "material_id": "...",
  "topic": "Moving day",
  "level": "A2",
  "audio_url": "https://...подпись...",
  "already_submitted": false
}
```

Текст уровня равен `users.current_level`. На день выбирается опубликованный материал этого уровня, который пользователь ещё не сдавал. Если таких нет, берётся любой опубликованный этого уровня, а повторная сдача разрешена не раньше чем через 14 дней.

`audio_url` — подписанная ссылка на бакет, жизнь 15 минут. Бакет приватный.

Конспект, от 200 до 2000 символов:

```
POST /v1/listening/{material_id}/submissions
{ "summary": "Anna moved the meeting..." }
→ 202 { "submission_id": "..." }
```

Вторая сдача того же материала в те же сутки отвечает `409` и возвращает прежний `submission_id`.

```
GET /v1/listening/submissions/{id}
→ {
  "status": "pending|done|failed",
  "meaning_score": 0.75,
  "language_score": 0.6,
  "missed_facts": ["Anna will send the notes."],
  "comments_ru": "..."
}
```

Воркер, задача `grade_summary`, модель `gpt-6.1-terra`, `reasoning_effort=low`. На входе транскрипт, `key_facts` и текст ученика. Оценка смысла — доля фактов, которые покрыты своими словами, от 0 до 1. Оценка языка — 0 до 1 за грамматику конспекта, без требования копировать исходные формулировки. Порог «зачтено» для XP: смысл ≥ 0.6. XP 15, ключ `xp:listen:{submission_id}`. Задание в `daily_tasks` типа `listening_summary` создаётся планом дня, если на сегодня нет другого listening и модуль ещё открыт; сдача по `GET /today` и по этому эндпоинту — одна и та же запись.

Сырой голос пользователя по-прежнему не хранится. Учебный файл в бакете — копия текста, не запись ученика.

## 3. Экзамен

Допуск: активный план, текущий модуль завершён по правилу v1.1. XP на допуск не влияет.

Экзамен состоит из десяти закрытых вопросов уровня «текущий + один шаг» (A1→A2, …, C1→C2; с C2 экзамен не предлагается) и одного звонка по сценарию `slug=level-up`, потолок 3 минуты. Вопросы берутся из `placement_items` с фильтром целевого уровня. Если банка не хватает, релиз не включает экзамен этого уровня: это дыра контента, не повод звать модель за вариантами ответов в рантайме.

```
GET /v1/exam
→ { "available": true, "target_level": "B1" }

POST /v1/exam
→ { "assessment_id": "...", "items": [ ... ] }

POST /v1/exam/{id}/answers
{ "answers": [ { "item_id", "choice" } ] }
→ { "call": { "call_id", "ticket" } }
```

Звонок идёт тем же сокетом, что v1.0. Сценарий level-up задаёт ментору короткие вопросы и запрещает длинные монологи. После `call_ended` клиент опрашивает:

```
GET /v1/exam/{id}
→ { "status": "pending|done|failed", "assigned_level": "B1", "passed": true }
```

Судья `gpt-6.1-terra`, `reasoning_effort=low`, на входе: доля верных закрытых, транскрипт, целевой уровень. Ответ:

```json
{
  "assigned_level": "B1",
  "passed": true,
  "notes_ru": "Держит прошедшее время, путает артикли."
}
```

`passed=true` только если `assigned_level` строго выше `users.current_level` и закрытая часть не ниже 60%. Иначе `passed=false`, уровень в профиле не меняется, в `level_assessments` запись всё равно есть. Повтор экзамена того же целевого уровня — не раньше 7 дней.

При `passed` XP 50, ключ `xp:exam:{assessment_id}`.

## 4. Инфраструктура

Новый сервер не арендуется. Объём каталога аудио и цена одного разбора Terra — в [расчёте ёмкости](capacity-and-cost.md). К уже существующему бакету добавляется префикс `listening/`. Жизненный цикл бэкапов Postgres не меняется.

Подписанные ссылки выдаёт `core` ключами бакета из env. Воркер пишет объекты тем же ключом. Публичного чтения бакета нет.

В PostHog: `listening_started`, `listening_submitted`, `exam_started`, `exam_passed`, `exam_failed`.

Если 12 текстов и экзаменационные банки не загружены, релиз выкатывается флагом `LISTENING_ENABLED` и `EXAM_ENABLED` в env, оба по умолчанию выключены, пока сид не прогнан. Код и миграции от контента не зависят.

## 5. Чего в этой версии нет

Свободный чат без сценария, смена голоса, хранение аудио ученика, ручная правка уровня из клиента, отдельный сервис оценки, синтез аудирования в момент запроса.
