# v1.1 — LMS, SM-2, план

Спецификация недель 6–8. Голос, биллинг и процессы те же, что в [v1.0](low-level-v1.0.md). Новый процесс не заводится.

## 1. Результат

После звонка у ученика на завтра появляются 2–3 задания из его ошибок, а слова из словаря возвращаются по SM-2. Есть личный план из модулей, стрик по локальной полуночи и XP за полезное действие. Уровень языка план не меняет.

Готово, когда повтор задания `process_call` не плодит вторую пачку карточек, «сегодня» совпадает с датой в часовом поясе пользователя, а пропущенный день уменьшает стрик на следующий заход.

## 2. Что добавляется

Тот же `ai-worker`. Задача `process_call` после отчёта и словаря дописывает задания. Новая задача `generate_plan` создаёт и пересобирает `learning_plans`.

`core` отдаёт день, принимает оценку карточки и считает SM-2, XP и стрик. Формулу повторений воркер не трогает: он только вставляет новые строки словаря так же, как в v1.0.

## 3. План

Один активный план на пользователя. Поля: `status` (`active|archived`), `version`, `goal` (копия цели на момент генерации), `modules`, `current_module_idx`.

Модуль:

```json
{
  "title": "Созвоны",
  "goal": "Удержать стендап на 3 минуты",
  "scenario_slugs": ["standup", "code-review"],
  "required_task_count": 12
}
```

Модулей 4–6. Каждый ссылается на уже существующие `scenarios.slug`. Воркер не выдумывает сценарий, которого нет в каталоге: неизвестный slug отбрасывается. Если после фильтра модуль пуст, план не активируется, задача падает и остаётся старая версия.

Генерация: `gpt-6.1-terra`, `reasoning_effort=low`, на входе цель, уровень и последние три `summary`. Старый активный план становится `archived`, новый пишется следующей `version` и сразу `active`.

```
GET /v1/plan
→ { "version": 2, "current_module_idx": 0, "modules": [ ... ] }

POST /v1/plan/regenerate
→ 202 { "job_id": "..." }
```

Пересборка не чаще одного раза в сутки на пользователя. Пока задача не закончилась, `GET` показывает прежний план.

Модуль завершён, когда каждый его `scenario_slug` есть хотя бы в одном `completed`-звонке пользователя и число выполненных `daily_tasks` с момента активации версии не меньше `required_task_count`. Тогда `current_module_idx` увеличивается. На последнем модуле индекс не растёт: экзамен, который этот факт откроет, входит в v1.2.

## 4. Задания из звонка

Воркер на один звонок создаёт не больше трёх `daily_tasks` на дату «завтра» в часовом поясе пользователя. Если на эту дату уже 8 незакрытых заданий, новые не добавляются.

`source_key` = `{call_id}:{n}` и он unique. Повтор задачи упирается в ключ.

Типы v1.1: `vocab`, `grammar_drill`. `listening_summary` и экзамен — v1.2.

`vocab`:

```json
{
  "vocabulary_id": "...",
  "lemma": "commute",
  "pos": "verb",
  "prompt": "Скажи по-английски: ездить на работу",
  "answer": "commute"
}
```

`grammar_drill`:

```json
{
  "mistake_span": "he go",
  "prompt": "Исправь: He go to work every day.",
  "answer": "He goes to work every day.",
  "explanation_ru": "В третьем лице нужно -s."
}
```

Оба типа проверяются на сервере точным сравнением после `trim` и свёртки пробелов, без модели. Ответ пользователя пишется в `result`, `completed_at` ставится при любом ответе. Карточку SM-2 двигает только задание `vocab`: верный ответ проходит как оценка `good`, неверный как `again`. `grammar_drill` карточку не создаёт и чужой `ease_factor` не меняет.

```
GET /v1/today
→ {
  "date": "2026-11-20",
  "reviews": [ { "vocabulary_id", "lemma", "translation", "context_sentence" } ],
  "tasks": [ { "id", "task_type", "payload", "completed_at" } ]
}

POST /v1/tasks/{id}/answer
{ "text": "He goes to work every day." }
→ { "correct": true, "explanation_ru": "..." }
```

`reviews` — карточки с `next_review_at <= конец сегодня` и `status=learning`, не больше 20 за день. Это отдельные от `daily_tasks` показы.

```
POST /v1/vocab/{id}/review
{ "grade": "again|hard|good|easy" }
→ { "next_review_at": "..." }
```

## 5. SM-2

Состояние карточки: `repetitions`, `ease_factor` (старт 2.5), `interval_days`, `lapses`, `last_reviewed_at`, `next_review_at`.

Оценки в качество SM-2: `again=1`, `hard=3`, `good=4`, `easy=5`.

* `again`: `repetitions=0`, `interval_days=1`, `lapses+1`, ease уменьшается на 0.2 и не опускается ниже 1.3.
* Иначе ease: `EF' = EF + (0.1 - (5-q) * (0.08 + (5-q) * 0.02))`, нижняя граница 1.3.
* Успех (`hard` и выше): если `repetitions` было 0, интервал 1 день; если 1, интервал 6 дней; дальше `interval = round(interval * EF')`. Затем `repetitions` увеличивается на 1.
* `easy` умножает получившийся интервал на 1.3.
* `next_review_at` = локальная полночь пользователя плюс интервал в днях, хранится в UTC.

## 6. XP и стрик

XP пишется в `xp_events` и прибавляется к проекции `users.xp_points` в той же транзакции. Ключ идемпотентности обязателен.

| Событие | XP | Ключ |
| :--- | :--- | :--- |
| Звонок завершён, не меньше 3 реплик пользователя и не короче 60 секунд | 20 | `xp:call:{call_id}` |
| Верный ответ задания | 5 | `xp:task:{task_id}` |
| Оценка карточки не `again` | 2 | `xp:review:{vocab_id}:{utc_date}` |

Короткий или пустой звонок XP не даёт. Один пользователь не получает XP за вторую оценку той же карточки в те же сутки UTC.

Стрик. Квалифицирующий день — день в `users.timezone`, в который был хотя бы один XP. На заходе `GET /v1/today` сравнивает `last_active_on` с вчерашней локальной датой. Совпало со вчера — стрик сохраняется. Совпало с сегодня — не меняется. Иначе `streak_days=0`, и если сегодняшний день уже квалифицирован, становится 1. `last_active_on` обновляется в момент начисления XP, не в момент открытия сайта.

```
GET /v1/progress
→ { "xp_points": 120, "streak_days": 4, "last_active_on": "2026-11-19" }
```

## 7. API, которое остаётся прежним

Звонок, сокет, ЮKassa, placement и чтение словаря не меняют контракт v1.0. `GET /v1/vocab` дополнительно отдаёт `ease_factor`, `interval_days`, `next_review_at`, чтобы экран словаря показывал срок.

## 8. Инфраструктура

Новых серверов нет. Насколько генерация плана и карточки без модели добавляют к счёту, посчитано в [расчёте ёмкости](capacity-and-cost.md). Тот же VPS, тот же Postgres, тот же Redis. Нагрузка дня — чтение карточек тысячей DAU — на этой машине меньше одного голосового часа.

В PostHog добавляются `review_graded`, `task_answered`, `plan_ready`, `streak_continued`.

## 9. Вне этого релиза

Аудирование, экзамен, смена `current_level`, синтез учебных аудио, отдельный сервис LMS.
